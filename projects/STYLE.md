# 프로젝트 상세 페이지 작성 규칙

`projects/nav-robot`을 고치며 정한 것들. 다른 프로젝트도 같은 방식으로 맞춘다.
**고치기 전에 이 문서를 먼저 읽는다.** 규칙이 바뀌면 여기부터 고친다.

> **각 페이지의 `index.html` 이 원본이다.** 예전에는 md 를 빌드해 HTML 을 만들었지만
> 그 빌더(`_portfolio-redesign/build.py`)는 폐기했다. 사용자가 HTML 을 직접 고치는데
> 빌더가 그 위에 덮어써서 수정이 날아간 적이 있다. **다시 만들지 않는다.**

곁 문서 — `PRINT.md`(A4 인쇄·PDF 저장 기준) · `nbsp.py`(줄바꿈 도구)

---

## 1. 문체

| 자리 | 종결 | 예 |
|---|---|---|
| 절의 **설명 줄**(리드) | `~합니다` | `Autodesk Fusion으로 설계해 3D 출력합니다.` |
| **목록 항목** | 개조식 명사형 | `압력센서를 당기면 어떤 상태에 있든 PAUSED로 전환` |
| **Troubleshooting 값** | 개조식 | `오도메트리가 끊기면 간 거리를 모름` |
| **Impact 라벨** | 개조식 | `엘리베이터 1층→5층 이동` |

**마침표**
- 목록 항목·Impact 라벨 — 안 찍는다
- Troubleshooting 값 — **문장 사이에만** 찍고 **끝에는 안 찍는다**
  `주행이 간헐적으로 멈춤. 조건 특정 불가`

**쓰지 않는 것**
- 시적·과장 표현 — `사용자는 로봇이 잘못 움직이는 것을 눈으로 볼 수 없습니다`
- 군더더기 도입부 — `직접 만든 하드웨어는 손잡이뿐입니다`, `로봇에 보내는 신호를 전부 여기에 모았습니다`
- 사람을 탓하는 말 — `부정적인 반응이 나와` → `원하지 않는다는 답을 듣고`
- 대구(`A가 아니라 B`) — 합격 자소서 표본에서 중위 0~0.9개/천자. 남발 금지
- 굵게(`**`) — 본문에서는 쓰지 않는다. 절 제목이 이미 강조다

## 2. 줄바꿈 — 문장 중간에서 끊기지 않게

빌더가 **쉼표·마침표 뒤에서만 줄이 바뀌도록** 절 안의 띄어쓰기를 줄바꿈 없는 공백으로 바꾼다
(`clause_wrap`). 한국어는 어절마다 띄어 쓰므로 그냥 두면 아무 데서나 끊긴다.

> **절 하나는 한글 20자 이내.** 넘으면 규칙이 **통째로 건너뛰어진다.**

20자가 상한인 이유: 폰(390px)에서 본문 한 줄이 21자다. 더 긴 절에 줄바꿈을 막으면
이번엔 단어 한가운데가 잘린다.

**리듬은 문장 길이가 아니라 문장 개수로 준다.** 절은 짧게 유지하고, 값마다 문장을 1~3개로 달리한다.
(합격 자소서 36명 계측: "AI틱하다"의 정량 원인은 문장 길이의 균일함)

**강제 줄바꿈** — 줄 끝에 역슬래시 `\`를 붙이면 `<br>`. 문단을 쪼개지 않고 줄만 나눈다.
```
ITRC 과제로 만든 실내 안내 로봇입니다.\
시각장애인 사용자가 손잡이를 잡고 걸으면 목적지까지 데려다줍니다.
```

## 3. 수치

- **수치로 쓸 수 있는 건 전부 수치로.** `CPU를 많이 씀` → `CPU 570% 점유`
- **근거 없는 수치 금지.** 코드·기록에서 확인하고, 확인 못 하면 쓰지 않는다
- **발표자료와 코드가 다르면 코드가 실제.** (예: `PreferForward.penalty` 슬라이드 5.0 / 코드 20.0)
- 근거 위치를 `overrides.yaml` 주석에 남긴다

**소재를 찾을 때** — 저자가 중요한 설계 노트에 `■` 표식을 단다.
`grep -rn '■' <저장소>` 한 번이면 "여기 봐라"고 스스로 표시해 둔 자리가 전부 나온다.
파일마다 관례가 달라서 `■`가 없는 파일도 있다. 결함 기록은 `.claude/FINDINGS.md`,
설계 결정은 `.claude/DECISIONS.md`.

## 4. 도판

### 마크업
그림 하나는 `figure` 로 감싸고 `img` 에 등급 클래스를 준다.

```html
<figure class="figure">
  <img class="figure__img figure__img--arch" src="../../assets/img/<slug>/x-arch.svg" alt="그림이 말하는 것">
</figure>
```

| 클래스 | 쓰는 자리 |
|---|---|
| `figure__img--arch` | 아키텍처 도면. 100% · 글상자를 넘어 넓게 |
| `figure__img--diagram` | 설계 도판 |
| `figure__img--diagram-tall` | 세로로 긴 도판. 2단에서 빠져나와 한 폭을 다 쓴다 |
| `figure__img--screen` | 화면 캡처 |
| `figure__img--photo` | 사진 |
| `figure__img--invert` | 다크 모드에서 반전시킬 흑백 그림 |

글 옆에 세울 때는 `contrib-side` 안에 `contrib-side__text` 와
`contrib-side__figs` 를 나란히 둔다. `contrib-side--wide` 는 그림 쪽을 넓게.

영상은 **임베드와 링크를 함께** 둔다. 인쇄하면 iframe 이 빠지고 링크만 남는다.

```html
<p class="video-url">영상 <a href="https://youtu.be/ID">youtu.be/ID</a></p>
```

CSS `content: attr()` 로 주소를 찍으면 안 된다 — 선택도 복사도 안 된다.

### 아키텍처 도면 밀도
`sona-arch.svg` 가 기준이다. **viewBox 폭 1392** 로 통일한다.
글자 크기는 SVG 안에서 고정이고, 실제로 읽히는 크기는 표시 폭이 정한다.

```
표시 pt = 원본 font-size × 515.9 ÷ viewBox 폭
```

515.9pt 는 A4(여백 16/14mm)의 본문 폭 182mm 다. 자세한 것은 `PRINT.md` 0-1 절.
**캔버스를 좁혀 글자를 키우려 하면 화면 밀도가 무너진다** — 한 번 겪었다.
배포본 SVG 는 폰트를 base64 로 품은 자기완결 파일이라 외부 참조가 없다.
휠체어 도면의 사양과 메모는 `wheelchair-parking/ARCHITECTURE.md`.

### 규칙
- **캡션은 기본적으로 달지 않는다.** 대신 `alt` 로 대체 텍스트를 반드시 넣는다
- 대체 텍스트는 **그림이 말하는 것**을 적는다. `설계 도판` 같은 종류명은 안 된다
- 그림 안에 문장을 박지 않는다 — 줄바꿈이 안 되고 검색·복사·번역이 안 된다.
  라벨만 그림에 두고 문장은 본문으로
- **도판이 본문과 맞는지 확인한다.** 절 주제가 바뀌면 도판도 바꾸거나 뺀다

## 5. 절 구성

**Impact** — 카드 4개. 넷이면 한 줄에 넷으로 선다
- 머리는 **한 일**을 쓴다. 숫자를 머리로 올리면 네 칸이 수치 자랑이 된다
- 숫자는 아랫줄에 근거로
- 라벨을 **목록**으로 주면 한 항목이 한 줄이 된다 (줄 나눔이 글자 수에 좌우되지 않게)

**Background** — 무엇인지 한 줄 → 어떻게 쓰는지 한 줄 → (빈 줄) → 선행 한계 → 도판 → 인터뷰 요구 → 시스템 구성

**Contributions** — 절마다: 제목 · 설명 1~2줄 · 항목 2~3개 · (옆 도판)

**Troubleshooting** — `문제 / 원인 / 해결 / 결과`. 라벨은 이 넷만 인식된다

## 6. 조판 (CSS, 이미 적용됨 — 건드릴 일 없음)

- **크기 8단**: 41.6 · 34 · 25.6 · 20.8 · 17.6 · 15.2 · 14.4 · 12.8px

  — 안쪽일수록 좁아야 한다
- 절마다 왼쪽에 세로선
- 목록 글자는 설명보다 두 단 작게(15.2 → 12.8px)
- 글꼴은 구 사이트와 같은 Pretendard CDN 원본. `-webkit-font-smoothing`을 넣지 않는다

## 7. 고치고 나서

고칠 파일은 `projects/<slug>/index.html` 이다. 빌드 단계는 없다.

한글 문장을 넣거나 고쳤으면 **줄바꿈을 먼저 통과시킨다.**

```bash
python3 projects/nbsp.py "카메라를 휠체어로 옮김, 먼 구간이 안 찍혀 개편"
```

나온 결과를 그대로 붙여 넣는다. 눈에는 보통 공백과 같아 보이지만 쉼표·마침표
뒤가 아닌 띄어쓰기가 NBSP 로 바뀌어 있다. 절 하나가 20자를 넘으면 도구가
**아무것도 하지 않고 원문을 돌려준다** — 그때는 문장을 쪼갠다.

점검
- 1280px 와 375px 에서 이미지 실패·가로 넘침·콘솔 오류 0
- 새 도판·새 배치는 **반드시 이미지로 열어 눈으로 확인**한다
- 인쇄로 뽑을 페이지는 `PRINT.md` 8절 체크리스트를 PDF 를 보며 채운다

## 8. PDF 로 저장할 때

머리글 오른쪽 프린터 단추(또는 `Cmd+P`)로 뽑는다. 규약은 `PRINT.md` 에 있고,
자주 걸리는 것만 여기 적는다.

- **A4 · 여백 16mm/14mm · 본문 182mm(515.9pt).** 이 값에서 모든 환산이 나온다
- **인쇄 폭은 687.9px 라 화면용 미디어쿼리가 켜진다.** 좁은 화면 규칙이 지면에
  딸려 들어온다 — 인쇄 전용 규칙을 쓸 때 늘 확인한다
- `break-inside: avoid` 는 **보장이 아니라 "되면 지킨다"** 다. 반드시 붙여야 하는
  덩어리는 크기를 줄여서 한 쪽에 들어가게 만든다
- 도판을 쪽에 맞출 때는 **높이가 아니라 폭으로 묶는다.** 높이로 묶으면 가로세로
  비가 다른 두 그림이 서로 다른 배율로 줄어 글자 크기가 어긋난다
- 영상 iframe 은 인쇄에서 빼고 링크만 남긴다
- `orphans` · `widows` 는 크롬 기본값이 2 다

## 9. 하지 말 것

- **본문을 통째로 다시 쓰지 않는다.** 사용자가 `index.html` 을 직접 고친다.
  내가 마지막으로 본 내용이 현재 내용이라고 가정하면 안 된다 — 고치기 전에
  `git status` 로 미커밋 변경을 먼저 본다. 바꿀 문장만 교체한다
- **빌더를 다시 만들지 않는다.** md 를 HTML 로 굽는 단계가 되살아나면
  사용자의 직접 수정이 또 덮인다
- 가로 스크롤(드래그)로 도판을 보게 하지 않는다
- 사용자가 지시하지 않은 본문 변경을 하지 않는다. 제안은 하되 반영은 확인받고
