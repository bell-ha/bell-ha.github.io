## 규칙 R1~R10 — 전부 만족해야 한다

- **R1 viewBox 가로 ≤ 900.** 인쇄 본문 폭이 182mm = 515.9pt 이므로

  기존 `sona-arch.svg` 는 viewBox 1392 라 글자가 종이에서 5.2pt 로 찍힌다 — **그 실수를 반복하지 않는다.**

## 재료 — 코드에서 확인한 사실만 쓴다

### V1 — 차가 휠체어를 본다 (`src/v1_aroundview/`)
- 입력: 차량에 달린 **어안 카메라 2대**(Left · Rear) = 어라운드뷰
- 대상: 휠체어에 붙인 **ArUco 마커 25 × 25 cm**
- 흐름: 마커 검출 → 왜곡 보정(K 3×3 intrinsic · D 4×1 fisheye) → **SolvePnP** → tvec·rvec
- 보정: **Ridge Regression 보정층** — 잔차가 거리·각도에 따라 체계적으로 치우치는 것을 학습으로 상쇄
- 안정화: **칼만 필터** (전·후진 200 mm/s · 회전 0.3 rad/s 운동 모델)
- 계획·제어: **A\* 경로계획 → 경로 추종 → CAN → AgileX TRACER**
- 도달: **8단계 중 7단계가 실기체에서 동작**
- 막힌 곳: 휠체어가 어라운드뷰 바깥에서 출발해 **먼 구간이 아예 안 찍힘**

### V2 — 휠체어가 차를 본다 (`src/v2_vision/jetson_nano/`)
- 플랫폼: **Jetson Nano 4GB** · 카메라 1대(15 fps) · **측면 초음파 2 · 전방 초음파 1 · IMU**
- 인식: **YOLOv8 부위 6종** — license_plate · car_emblem · door_handle · fuel_cap · tail_light · side_mirror
- 추정: **번호판 335 × 155 mm 국가 표준을 자로** → 핀홀 `D = H_real·f / h_px` ·
  yaw(폭/높이 비율) · bearing `atan((x−cx)/f)`
- 판단: **`AlignmentPlanner` 상태기계** (`guidance/common.py:175`)
  - **VISION** 국면 — 사이드미러 앵커 IBVS. 임계 `EPS_U 0.035` · `EPS_SCALE 0.060`
  - **SONAR** 국면 — 측면 초음파 앞뒤 차이로 평행. 임계 `EPS_SONAR_DIFF 0.035`
  - 두 국면 모두 **여덟 프레임 연속 허용범위**여야 넘어간다 (`STABLE_FRAMES = 8`)
- 지시: **TURN LEFT · TURN RIGHT · MOVE FORWARD · MOVE BACKWARD 네 종류뿐**, 나머지는 전부 정지
- 기준 자세: **teach & repeat** — `teach.py` 가 사람이 한 번 잡아 준 자세를 `real_front_goal.json` 에 저장
- 출력: **ESP32 USB 시리얼 → 서보 → 휠체어 조이스틱**(JUVO B4)
- 스레드: **UI·시리얼 33Hz 스레드 / YOLO 메인 스레드**, 화면 갱신 10Hz

### V1 인식 과정 (발표자료 0301 9쪽 — 원문 텍스트)
```
Left Frame / Rear Frame
  → Detect Markers → Undistort points
     K(3x3 intrinsic matrix) · D(4x1 fisheye distortion coefficients)
  → SolvePnP (25cm x 25cm) → tvec(마커까지의 3D 벡터) · rvec(회전)
  → Processing
     Left_center(x,y) · Left_heading(θ) · Rear_center(x,y) · Rear_heading(θ)
  → Step1 3D → 2D
  → Step2 Ridge Regression
     g: 바닥거리(m) · b: 화면 내 마커 각도(deg)
     v: 마커가 카메라를 바라보는 각도(deg) · reproj: PnP 품질(PnP 전후 px 차이)

카메라 파라미터
  Left Camera : Left_base=(200, 270)   h_left=110 cm    Ang_left=157   Yaw_trim=8
  Rear Camera : Rear_base=(301.4, 540) h_rear=105.5 cm  Ang_rear=90    Yaw_trim=3
  마커 Id : 0 = front, 1 = back
```
슬라이드가 쓰던 사진은 `notes/wc-arch/s9_*.png|jpg` 로 빼 뒀다. **참고만 하고 그림은 새로 그린다** —
슬라이드를 그대로 캡처하면 글자가 종이에서 4pt 아래로 떨어진다.

## 현재 사양 (sona-arch 기준)
```
viewBox     1392 × 1000     세로/가로 0.718 (상한 1044)
노드        160 × 66        가로의 11.5% — sona-arch 와 동일
글자        제목 17 · 부제 14 · 엣지 라벨 14 · 경계 라벨 14
이름표      'V2 — 휠체어가 차를 본다'  x=71 · baseline y=71 · 37px SemiBold · #0f172a
```

**표시 배율:** 본문 872px 에 넣으면 0.626 배 → 14px 글자가 화면 **8.8px**. sona-arch 와 같다.
종이(182mm)에서는 14px → **5.19pt**, 17px → 6.30pt.

> ⚠️ **초판은 viewBox 900 이었다.** 인쇄 8pt 하한을 맞추려던 것인데, 같은 872px 단에 넣으면
> 배율이 0.969 가 되어 글자가 화면에서 **1.55 배** 커진다. 사용자가 sona-arch 대비 너무 크다고
> 지적해 기준을 sona-arch 로 통일했다. **`표시 pt = font-size × 515.9 ÷ viewBox 폭` 공식은
> 그대로 유효하고, 하한만 8pt → sona-arch 수준(5.19pt)으로 바뀌었다.**

### 제목이 17 인 이유 (초판은 16이었다)
viewBox 900 · 노드 158 일 때 `번호판 자 335×155` 가 17px 에서 **139px / 여유폭 138px** 로 1px
넘쳐 16 으로 내렸었다. **1392 · 노드 160 에서는 여유폭이 140px 이라 같은 139px 가 들어간다.**
그래서 17 로 되돌렸고 V1·recog 와 일관된다.

## 이 도면이 말하는 것 두 가지
1. **카메라가 움직이는 쪽에 있다** — 「휠체어에 실린 것」 경계가 센서·인식·판단·구동을 전부 감싸고,
   차량은 경계 **밖**에 「계측 장치 없음」으로 혼자 서 있다. V1 과 나란히 놓으면 뒤집힌 게 보인다.
2. **구간마다 기준 센서가 넘어간다** — 카메라 → VISION, 측면 초음파 → SONAR.

## IMU · 전방 초음파 — 서보로 가는 경로가 실제로 있다

한때 이 두 센서를 연결선 없이 뒀다가 **틀린 판단이었음이 밝혀졌다.** github-b5 제보로
코드를 다시 읽고 확인했다 (`src/v2_vision/jetson_nano/experiments/straight_drive.py`).

| 경로 | 근거 |
|---|---|
| **IMU → 서보** `직진 중 방위 유지` | 방위 오차 → 목표 회전속도 → 자이로로 그 속도를 맞춤(캐스케이드) → 서보 편향. 적분항이 캐스터 틀어짐을 주행 중 학습 |
| **전방 초음파 → 서보** `30cm 자동 정지` | `FRONT_STOP_CM = 30.0` · `:195` `if state == "MOVE FORWARD" and 0.0 < front_v < FRONT_STOP_CM` |

내가 처음에 "VISION·SONAR 국면이 이 센서를 안 읽는다"고 한 것은 **맞다**
(`AlignmentPlanner.update(feature, sonar, image_shape)` 는 카메라 특징과 **측면** 초음파만 받는다).
틀린 것은 거기서 "그러니 경로가 없다"로 넘어간 부분이다. **정렬 국면이 아니라 이동 자체를
서보 단에서 보정하는 경로**로 붙어 있었다.

### ⚠️ 다만 층위가 다르다 — 본문을 쓸 때 주의할 것
이 두 경로는 **`experiments/straight_drive.py` 안에 있고, `main.py` 는 이 파일을 import 하지 않는다.**

```
main.py (통합 조종석)   카메라 + YOLO + 측면 초음파 → AlignmentPlanner → 지시 → 서보
                        IMU(yaw·gyro_z)와 전방 초음파는 화면 표시 전용 (E 키로 측정 토글)
straight_drive.py       키보드(W/S/A/D) 구동 + IMU 캐스케이드 + 30cm 자동 정지. 카메라/YOLO 불필요
```

즉 **"자동 모드가 주행 중 방위를 잡아 준다"는 말은 성립하지 않는다.** 두 기능은 구현돼 있지만
별도 실행 도구에 있다. 도면은 "V2 라는 시스템이 가진 제어 경로"를 그리는 것이라 넣는 것이 맞고,
실제로 최상위 `README.md` 표도 V2 를 **"IBVS + 초음파 + IMU → 조이스틱"** 으로 적고 있다.
**다만 본문이나 면접에서 "정렬 루프 안에서 돈다"고 말하면 과장이 된다.**

## 배치 — 한 줄기로 읽히게 (사용자 지시)

주 흐름을 **R1 한 행에 6열로 폈다.**
```
카메라 → YOLOv8 → VISION 국면 → 지시 4종 → ESP32 서보 → 조이스틱
```
곁가지는 이 줄기에 붙는 형태로 내렸다 — `번호판 자`(YOLO 아래), `측면 초음파 → SONAR 국면`,
`teach & repeat`(판단 경계 아래), 그리고 `IMU`·`전방 초음파`는 아래 두 레인으로 달려
**ESP32 서보 밑변으로 올라붙는다.**

이전 배치는 센서 3개가 왼쪽에 쌓이고 판단·구동이 오른쪽에 몰려 갈래가 여럿으로 보였다.
글자를 줄이지 않고 배치만으로 풀었다 — **제목 17 · 부제 14 그대로다.**

## 정직하게 그린 부분 (남아 있는 것)
- `mAP50`·`검출 6배`·`conf` 수치는 넣지 않았다 (홀드아웃이 아니라서).
- V3(UWB)는 넣지 않았다 (실험 미시작).
- 「AlignmentPlanner · 8프레임 연속」 경계 안에는 **VISION·SONAR 두 국면만** 들어 있다.
- `teach & repeat` 화살표는 SONAR 노드가 아니라 **planner 경계**에서 끝난다 — 기준 자세는
  특정 국면 전용이 아니라 두 국면 공통이기 때문이다.

## 대체 텍스트 (R8) — `<desc>` 에 들어 있다
> 카메라와 초음파, IMU 가 모두 휠체어에 실려 있고 주차된 차량에는 계측 장치가 없다. 카메라가 잡은
> 부위 6종을 번호판 규격으로 환산해 VISION 국면이 사이드미러로 시야를 맞추고, SONAR 국면이 측면
> 초음파 앞뒤 차이로 평행을 맞춘다. 판단 결과는 네 가지 지시가 되어 ESP32 서보가 조이스틱을 움직인다.

## 폰트 파일명은 `_v2_*` — 되돌리지 말 것
세 세션이 이 폴더에서 도면을 그렸고, 모두 sona-arch 관례인 `_sub_*.woff` 를 써서 **서로의 글자표를
덮어썼다.** 나중에 구운 쪽이 이기고, 그 시점에 SVG 를 만든 세션은 남의 글자표를 내장하게 된다.

**이 사고는 렌더로 안 보인다.** 작업 기기에 Pretendard 가 깔려 있어 빠진 글자가 시스템 폰트로
조용히 대체된다. **Pretendard 가 없는 기기(= 채용 담당자 PC)에서만** 드러난다.
이 장은 `_v2_*`, V1 구조는 `_v1_*`, V1 인식은 `_recog_*`. 새 도면은 반드시 자기 접두사를 붙인다.

### 커버리지는 weight 를 나눠서 재야 한다
합집합으로 재면 **굵은 글자만 빠진 경우를 못 잡는다.** `.nt`·`.fl`·`.tm` → weight 600,
`.ns`·`.el` → weight 400.

두 가지 함정:
- **HTML 엔티티를 풀지 않으면 멀쩡한 도면이 불합격으로 나온다.** `·` 가 `&#183;` 로 나간다.
- **`class` 없는 `<text>` 는 어느 weight 로도 검사되지 않는다.** 개수를 따로 세어 0 인지 본다.

※ 이 빌더는 **하나의 글자표를 두 weight 에 똑같이 굽는다.** 그래서 두 weight 의 cmap 이 구조적으로
같고 한쪽만 빠질 수 없다. weight 별로 다른 글자표를 쓰는 빌더는 별도로 확인해야 한다.

   선 오른쪽으로 밀었다. **라벨은 엣지가 아니라 선분 교차 검사로 안 잡힌다.**

   안티에일리어싱이었다. 크롭해 3배 확대해서 확인했다. 그래서 이름표를 넣을 때 캔버스를 안 늘렸다.
