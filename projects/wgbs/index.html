Background

WGBS(전장 유전체 메틸화 분석) 절차는 데이터 분석 전문가가 R로 작성한 여러 단계의 스크립트였습니다. 연구자가 그것을 쓰려면 명령줄에서 도구를 오가며 단계마다 직접 실행해야 하고, 한 단계라도 순서나 인자를 틀리면 끝까지 가서야 알게 됩니다.

정작 이 분석을 매일 돌려야 하는 사람은 프로그래밍 경험이 없는 연구자입니다. 그 절차를 도구로 만드는 일을 맡았습니다. 연세대학교 운동생리학연구실 소속 과제이고, 서울대학교·연세대학교 연구진과 함께 진행했습니다.

Contributions

순서를 UI가 강제하게 했다

Tkinter로 9단계 순차 진행형 화면을 만들고, 단계를 넘어갈 때 입력을 검증해 실행 전에 오류를 막았습니다. 잘못된 조합으로 몇 시간짜리 분석을 돌리고 나서 실패를 알게 되는 것이 가장 큰 비용이었습니다.

GUI와 콘솔이 같은 백엔드를 호출한다

화면용 코드와 명령줄용 코드를 따로 두면 같은 데이터에서 다른 결과가 나올 수 있습니다. 두 진입점이 동일한 분석 백엔드를 호출하도록 만들어, 어느 쪽으로 실행해도 결과가 일치하는 것을 보장했습니다.

기존 분석 모듈을 고치지 않고 화면에 붙였다

이미 검증된 분석 코드는 콘솔에 진행 상황을 출력하도록 짜여 있었습니다. 그 코드를 수정하면 검증을 다시 해야 하므로, 콘솔 출력을 코드 변경 없이 GUI 로그로 실시간 중계하는 구조로 감쌌습니다. 장시간 연산은 백그라운드 스레드로 분리해 실행 중 화면이 멈추지 않게 했습니다.

설치 과정을 없앴다

실행 환경을 자동으로 탐지하고, 필요한 R 실행 환경을 함께 담아 단일 실행 파일로 배포했습니다. 연구자가 별도 설치 없이 받아서 바로 실행합니다. 실제 연구 데이터의 전 과정 분석에 사용됐습니다.
