Background

사설 CloudStack(가상 서버를 직접 띄우는 사내 클라우드) 위에 3노드 쿠버네티스 클러스터를 세우고, 커밋이 배포까지 이어지는 파이프라인을 붙였습니다.

퍼블릭 클라우드가 아니라는 것이 제약의 대부분이었습니다. 로드밸런서를 대신 만들어 주는 장치가 없고, 공인 IP는 하나만 받습니다. 그래서 무엇을 어떻게 외부로 꺼낼지를 먼저 정해야 했습니다.

Architecture

Contributions

IP 하나 위에서 포트로 모든 것을 가른다

공인 IP가 하나이므로 포트 규약을 먼저 정했습니다. SSH는 22 · 2201 · 2202로 노드를 가르고, 서비스는 쿠버네티스가 노드에 열어 주는 포트(NodePort) 번호를 그대로 외부 포트로 통과시켰습니다. 규약을 나중에 정하면 서비스가 늘 때마다 포트가 충돌합니다.

구축을 두 단계로 나눴다

Terraform으로 노드를 만들고(프로비저닝), Ansible로 설정합니다(구성). 순서는 마스터 준비 → Calico 네트워크 → 워커 조인 → MetalLB 준비 → 앱 배포 다섯 단계입니다. 마스터가 준비된 뒤에야 워커가 조인할 수 있으므로 플레이를 쪼개 경계를 두었습니다.

다시 돌려도 안전하게 만들었다

초기화와 조인은 이미 끝났으면 건너뛰게 했습니다. 구축 스크립트는 한 번 성공하는 것보다 몇 번을 돌려도 같은 상태가 되는 것이 중요합니다. 중간에 실패하면 처음부터 다시 돌려야 하기 때문입니다.

LoadBalancer가 없는 환경을 정직하게 다뤘다

CloudStack에는 퍼블릭 로드밸런서가 없어서 type: LoadBalancer 서비스는 외부 IP를 받지 못하고 대기 상태에 머뭅니다. MetalLB를 설치해 컨트롤러가 뜬 뒤 IP 풀과 L2Advertisement까지 구성해 두었습니다. 거기까지입니다 — 실제 외부 접근은 공인 IP 하나에 포트포워딩을 걸어 NodePort로 내려보내는 방식이고, 클러스터에 type: LoadBalancer 서비스는 하나도 없습니다(30080 · 32080 · 30500 · 30001 네 개 모두 NodePort).

비밀값이 파일로 남지 않게 했다

워커 조인 토큰은 파일 대신 메모리로 넘겼습니다. 제출 뒤 저장소를 점검해 평문 API 키와 상태 파일을 분리했습니다.

Troubleshooting

서비스를 외부에서 열 수 없다

문제
앱을 올려도 브라우저로 접근할 방법이 없었습니다. type: LoadBalancer 서비스가 외부 IP를 배정받지 못하고 무한히 대기했습니다.
원인
그 타입은 클라우드 제공자가 로드밸런서를 만들어 준다는 전제 위에 있습니다. 사설 CloudStack에는 그 장치가 없습니다.
해결
MetalLB를 설치해 IP 풀과 L2Advertisement를 구성해 두고, 외부 접근은 공인 IP 하나에 포트포워딩을 걸어 NodePort로 내려보내는 방식으로 정리했습니다.
결과
GitLab · Jenkins · 컨테이너 레지스트리를 올려 커밋에서 배포까지 이어지는 것을 확인했습니다. 다만 실제 경로는 NodePort이며 MetalLB로 서비스를 노출한 것은 아닙니다. 노드가 3대이고 마스터가 1대라 마스터가 죽으면 클러스터가 멈추는 구성입니다 — 운영 환경과 같은 이중화는 아닙니다.
