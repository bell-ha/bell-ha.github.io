Background

음악 아티스트는 자기 작업을 모아 보여줄 곳이 없습니다. 인스타그램은 흐르고, 사운드클라우드는 음원만 담고, 웹사이트는 만들 줄 모릅니다. 코드 없이 자기 페이지를 만들고 공개하는 서비스를 2인 팀으로 만들어 실사용자를 받아 운영했습니다. 백엔드는 제가 전담했습니다 — 백엔드 5,519줄 중 5,493줄이 제 것입니다. 현재는 구조를 다시 잡는 중이라 도메인이 내려가 있고, 코드는 저장소에서 볼 수 있습니다.

까다로운 지점은 아티스트마다 보여줄 것이 다르다는 것이었습니다. 세션 연주자는 참여 앨범 이력이, 미디어아트 작가는 전시 사진이 본체입니다. 같은 틀에 넣으면 누군가는 항상 어색해집니다.

Architecture

Contributions

가장 고민한 것 — JSON 한 칸이냐, 템플릿별 스키마냐

콘텐츠 구조가 가변적이니 JSON 컬럼 하나에 통째로 담는 쪽이 가장 간단했습니다. 그러면 장르별·직업별 검색을 붙일 수 없고, 템플릿을 바꿀 때 데이터를 옮길 경로가 없습니다. 템플릿별로 정규화한 스키마를 택했습니다. 간단한 쪽이 아니라 나중에 되돌릴 수 있는 쪽을 골랐습니다.

직업 분류를 코드에 박지 않았다

직업 목록을 상수로 두면 직업이 하나 늘 때마다 배포해야 합니다. 2단 카테고리에 다대다로 두어, 행만 추가하면 됩니다. 바꿔야 하는 사람은 운영자이고 배포할 수 있는 사람은 개발자인데, 이 둘이 다르면 구조가 개발자를 계속 부릅니다.

진입 경로 셋을 토큰 하나로 수렴시켰다

로컬 가입 · Google OAuth · 이메일 OTP로 들어오는 길이 셋이었습니다. 진입만 셋으로 두고 이후 요청은 전부 하나의 JWT로 처리하도록 정리해, 인증을 확인하는 코드가 경로마다 갈라지지 않게 했습니다.

템플릿 중복을 서비스 계층으로 걷어냈다

profile.py 898줄 중 약 600줄이 템플릿 1과 2의 같은 코드였습니다. 공통 처리를 레지스트리로 묶어 서비스 계층으로 옮기고 라우터를 271줄로 줄였습니다. 옮긴 코드가 새 파일로 들어갔으니 전체 줄 수가 3분의 1이 된 것은 아닙니다 — 줄을 줄인 것이 아니라 같은 코드가 두 군데 있는 상태를 없앤 것입니다.

Troubleshooting

빈 데이터베이스에 붙이면 기동조차 되지 않았다

문제
운영 중인 데이터베이스 하나에만 의존하고 있었습니다. 서버가 뜰 때마다 테이블 변경과 외래키 재생성이 실행되는 구조여서 변경 이력도 롤백 수단도 없었고, 모델 정의와 실제 스키마가 어긋나 있었습니다.
원인
그 하나뿐인 운영 데이터베이스만 우연히 동작하고 있었던 것입니다.
해결
마이그레이션 도구(Alembic)로 옮기면서 자동 생성을 그냥 돌리지 않았습니다. 그러면 외래키를 전부 삭제하는 마이그레이션이 나옵니다. 운영 스키마를 먼저 뽑아 모델과 대조하고 차이를 하나씩 판정한 다음 이력을 시작했습니다.
결과
그 과정에서 ON DELETE CASCADE 27개가 운영에만 있고 모델에는 없다는 것을 찾았습니다. 그대로 새 환경을 만들었으면 사용자 삭제가 외래키 위반으로 죽었을 것입니다.

중복이 버그를 낳고 있었다

문제
템플릿 2만 쓰는 아티스트가 카테고리 목록에 영영 노출되지 않았습니다.
원인
공개 목록 조회가 템플릿 1 테이블만 보고 있었습니다. 같은 성격의 검색 API는 둘 다 보고 있어서, 어느 쪽이 맞는지가 코드 안에서 갈려 있었습니다.
해결
템플릿 중복을 레지스트리로 통합하면서 조회 경로도 하나로 합쳤습니다.
결과
중복을 줄이려고 시작한 작업에서 실제 버그가 함께 해결됐습니다.

화면만 막으면 API로는 뚫린다

문제
회원가입이 이메일 인증을 확인하지 않아 API를 직접 호출하면 미인증 주소로 가입됐습니다. 편집 화면에는 구현되지 않은 템플릿 버튼이 있어, 누르면 자기 공개 페이지가 404가 되는데 경고가 없었습니다.
원인
검증이 화면 쪽에만 있었습니다.
해결
인증 상태를 확인하고 소비하도록 고치고 시도 제한과 재발송 쿨다운을 넣었습니다. 미구현 템플릿은 화면에서 비활성화하고 서버도 등록된 번호만 받도록 했습니다. 저장이 네 섹션 병렬이라 하나만 실패해도 나머지는 이미 저장되던 것도 순차로 바꿔, 첫 실패에서 멈추고 서버가 보내는 사유를 그대로 보여주게 했습니다.
결과
pytest 86개로 회귀를 막았습니다.
